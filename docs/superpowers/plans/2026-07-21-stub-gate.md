# Phenom Stub-Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Skip the per-position detail HTTP GET on `phenom` boards for postings the existing deterministic gates already reject, cutting the Microsoft board from 1,580 detail GETs to ~458.

**Architecture:** `phenom.fetch` gains an optional `keep(stub) -> "drop"|"discard"|"hydrate"` predicate. Inside its existing `_row` closure it builds the canonical posting from the search stub via the existing `parse_position` (which already yields `description=""`), asks `keep`, and only calls the detail endpoint for `"hydrate"`. `run_fetch` builds that predicate from the filter parameters it already receives and passes it only for sources in `STUB_GATE_SOURCES`. `run_fetch`'s existing post-fetch loop still does **all** status tagging, so `keep` changes which HTTP calls happen and never which status a row gets.

**Tech Stack:** Python 3.11, pytest. No new dependencies. No schema change.

Design spec: [`docs/superpowers/specs/2026-07-21-stub-gate-design.md`](../specs/2026-07-21-stub-gate-design.md)

## Global Constraints

- **No schema DDL.** Prisma owns `apps/web/prisma/schema.prisma`; this change touches no schema and no fixture. The drift guard must stay green untouched.
- **Worker modules stay pure + dependency-injected.** No network, no keys, no real services in tests.
- **No new filter semantics.** `filter_postings`, `prefilter_postings`, `deterministic_screen` are reused verbatim; this change alters only *when* they run.
- **Watchlist path only.** `run_feed` and every non-`phenom` adapter must be provably unaffected.
- **Fail open.** Any unrecognised `keep` return value must hydrate. A broken predicate may cost HTTP requests; it may never lose a posting.
- **Python, 4-space indent.** Run everything from `apps/worker/`.
- **Test runner:** use `rtk proxy python3 -m pytest ...` — plain `pytest` is intercepted and mis-summarized in this environment.
- **Commits:** short imperative subject with a `type(scope):` prefix. Keep each commit green.

```python
def fetch(slug: str, company_name: str, session: requests.Session | None = None,
          timeout: int = 20, keep=None) -> list[dict]:
    """List a phenom board. `keep(stub) -> 'drop' | 'discard' | 'hydrate'` is an
    OPTIONAL fetch-cost optimization: the search stub already carries the title and
    location, which is everything the deterministic gates read, so a rejected
    posting can skip its detail GET (the dominant cost — one per position). 'drop'
    omits the posting entirely, 'discard' returns it un-hydrated (empty
    description) so the caller can still record it, 'hydrate' is the normal path.
    Any other value hydrates: a broken predicate must cost requests, never
    postings. keep=None disables the gate entirely."""
    host, domain = _parts(slug)
    search_url = f"https://{host}/api/pcsx/search"
    detail_url = f"https://{host}/api/pcsx/position_details"

    def _page(http, start):
        resp = http.get(search_url, params={"domain": domain, "start": start}, timeout=timeout)
        resp.raise_for_status()
        data = _require_ok(resp.json())
        return data.get("positions") or [], data.get("count")

    def _row(http, pos):
        pid = str(pos.get("id") or "")
        if not pid:
            return None  # no id can't dedup under (source, external_id)
        stub = parse_position(pos, company_name)  # description="" until hydrated
        if keep is not None:
            verdict = keep(stub)
            if verdict == "drop":
                return None       # never stored, no detail call
            if verdict == "discard":
                return stub       # stored un-hydrated, no detail call
        description = ""
        try:
            detail = http.get(detail_url,
                              params={"domain": domain, "position_id": pid}, timeout=timeout)
            detail.raise_for_status()
            description = _require_ok(detail.json()).get("jobDescription") or ""
        except Exception:
            pass  # one bad detail: keep the posting (search has title/loc/url), no desc
        return parse_position(pos, company_name, description)

    return paged_details(session, fetch_page=_page, build_row=_row)
```

def fetch_company(source: str, slug: str, company_name: str, *,
                  recipe: dict | None = None, keep=None, **kwargs) -> list[dict]:
    """Dispatch to the per-board adapter for `source` (lists a whole board).

    `recipe` is forwarded only to the recipe-driven executors (custom/browser) and
    `keep` only to the stub-gate adapters; plain adapters accept neither, so each
